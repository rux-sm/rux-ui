Layout rules

Token-only spacing

Trip bar inset

  • Inside a scheduler track, bars sit var(--rux-space-2) from top and bottom.
  • Bars sit var(--rux-space-2) away from day grid lines on each side.
  • Selected rings paint outward into the rail inset, leaving a visible var(--rux-space-1) gap all around.
  • Trip bars use var(--rux-space-2) body padding and reveal the details footer when selected.

Scheduler growth

  • Scheduler day columns use var(--rux-scheduler-day-min-width) as the horizontal fit floor.
  • Collapsed bars have a fixed height: var(--rux-trip-bar-collapsed-height).
  • Selected bars with the action toolbar use var(--rux-trip-bar-active-height).
  • Selection changes trigger the same row-height recalculation as expanding details.
  • Collapsed conflict bars add one control-height row so the conflict band and toggle stay visible.
  • Scheduler rows shrink or grow to the current bar height plus top and bottom inset.
  • Scheduler rows grow to show the full active or expanded trip bar.
  • All designed trip-bar rows stay visible; long text truncates inside its own row.
  • Trip bars do not overlap adjacent bus rows and should not clip their own rows.
  • Stacked lanes add lane height and lane gap.

Grid border

  • All scheduler and day dividers use var(--rux-border-width), currently one hairline.
  • Grid lines use var(--rux-border); inner details use an 8% foreground mix.
  • The rail background is var(--rux-bg) so bars read as raised objects.

Radius hierarchy

  • Scheduler rail uses var(--rux-radius-lg).
  • Trip bars use var(--rux-radius-md) because they are nested inside the rail.
  • Badges and bus labels step down to var(--rux-radius-sm) or full pills.

State color

  • Confirmed trips use the current accent token on the trip bar itself.
  • Fully paid trips show a success dollar-sign status icon.
  • Unconfirmed trips and pending summary icons use danger; late arrival text uses warning.
  • Single-day trips use the same row styling as multi-day trips inside a one-day span.

Height contract

Trip owns height, rail measures it

Trip bar height

  • All collapsed trip bars use var(--rux-trip-bar-collapsed-height).
  • Single-day and multi-day bars share this collapsed height.
  • The action toolbar contributes var(--rux-trip-bar-action-height): one control, two standard padding insets.
  • The details toggle contributes var(--rux-trip-bar-expand-height) and is hidden until selected.
  • Selected trips use var(--rux-trip-bar-active-height) so the action toolbar and details toggle are included.
  • Conflict rows add var(--rux-control-height) to the current collapsed or selected height.

Scheduler row height

  • Row height is the tallest visible trip bar in that bus row plus top and bottom inset.
  • The standard inset is var(--rux-space-2) above and below the bar.
  • When bars are stacked into lanes, row height is lane heights plus lane gaps plus the same outer inset.
  • The scheduler should recalculate row height after selection, expansion, conflict changes, or data refresh.

Do not stretch bars

  • Do not pin a bar with both top and bottom; that stretches the bar to the rail.
  • Use the bar height as the source of truth, then place it at the rail inset.
  • Expanded details and selected action bars must grow the scheduler row instead of clipping or overlapping.
  • Long text truncates inside its row; vertical overflow should be solved by row measurement.

Measurement hook

  • After calling setActive(), setExpanded(), or replacing trip data, measure the rendered bar.
  • A ResizeObserver on each visible trip bar keeps row height synchronized with UI state.
  • The demo rail sets --_rail-row-height to measured bar height plus the two rail insets.
  • Height changes should animate with the trip bar so the rail opens smoothly instead of popping.

Action animation

  • Selection animates the trip bar height to match the selected-state rows.
  • The action toolbar stays in layout with max-height: 0, hidden visibility, and no pointer events.
  • On selection, it animates to var(--rux-trip-bar-action-height) with opacity and slight vertical motion.
  • The same action set stays visible across widths; open trip is always the primary icon button.
  • Scheduler rail cells transition their measured min-height with the bar height.
  • Do not use display: none for the toolbar; display cannot animate and makes row growth pop.

Details availability

  • Inactive trip bars are scan-only and do not show the more details button.
  • Selecting a trip reveals the details toggle below the scan rows.
  • Details can expand only while the trip bar is active.
  • When a trip bar becomes inactive, expanded details collapse with the action toolbar.

Selection dismissal

  • Clicking an inactive trip bar body selects it and clears every other active bar.
  • Clicking the selected trip bar body again dismisses it and collapses expanded details.
  • Action buttons do not toggle selection; they run their command and keep the current bar selected.
  • The details toggle does not dismiss selection; it only expands or collapses the details row.
  • Pointer-down inside another trip bar immediately clears the previous active bar before the next click resolves.
  • Clicking outside all trip bars clears the active state and closes the action toolbar.
  • Selecting another trip bar clears the previous active bar, even across scheduler sections.
